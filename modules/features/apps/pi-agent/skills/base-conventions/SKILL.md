# Base conventions

Load this skill first for any task. It applies to code, comments, documentation, commit messages, and chat replies.

## Language

Use British English everywhere. Common replacements:

| British | Not |
|---|---|
| colour | color |
| behaviour | behavior |
| initialise, initialisation | initialize, initialization |
| customise, customised | customize, customized |
| organise, organised | organize, organized |
| recognise, recognised | recognize, recognized |
| serialise, serialised | serialize, serialized |
| normalise, normalised | normalize, normalized |
| prioritise, prioritised | prioritize, prioritized |
| optimise, optimised | optimize, optimized |
| analyse, analysed | analyze, analyzed |
| sanitise, sanitised | sanitize, sanitized |
| synchronise, synchronised | synchronize, synchronized |
| centre | center |
| labelled | labeled |
| cancelled | canceled |
| licence (noun) | license |
| catalogue | catalog |
| grey | gray |

Keep the spelling of code identifiers, command names, file paths, and third party APIs exactly as they are. Only prose changes.

## Writing

- Use short, direct sentences.
- Prefer plain words over jargon.
- Do not use em dashes, arrows, decorative bullets, curly quotes, or emoji.
- Do not use a long word when a short one will do.
- Explain the reason, not the obvious.
- Say what a thing does, not how impressive it is.
- Do not repeat the same point in different words.
- Keep headings short and in sentence case.

## Comments

- Only comment when the code cannot explain itself.
- Explain why, not what. The code already shows what it does.
- Keep a comment to one to three short lines.
- Use plain text and normal punctuation.
- Do not use decorative separators, arrows, or special symbols.
- Do not add a comment that only restates the next line.
- Do not add section labels for obvious groups such as "Fonts" or "Colours".
- Keep comments that record a bug, a workaround, an upstream limit, or a non obvious choice.
- Update or delete a comment when the code changes.
- Write comments in British English.

## Before finishing

- Read the changed text once for clarity.
- Check for American spellings.
- Remove any comment that adds nothing.
- Make sure the result is easy to scan.
